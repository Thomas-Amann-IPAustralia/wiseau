# Handover: scanned-page OCR work, 2026-11-03

Read this after `CLAUDE.md` and `STATUS.md`. It covers what the 2026-11-03 session
changed, what it measured, what is still undecided, and how to pick the work up
without repeating its mistakes. Branch: `ccr-e6d8e806-trej28` (31 commits ahead
of `main` at hand-over).

## The question being worked on

The user found the offline engines underperforming on scanned pages, and the
paid cloud APIs too costly for production. The session looked for the best
**local, no-API** design for scanned pages. Born-digital pages are settled:
PyMuPDF reads their text layer exactly (wer 0.019, 0.2 s/page).

**Standing user instruction: no paid API tokens** (Gemini, OpenAI) until the user
says otherwise. Every benchmark in this session was local.

## What shipped (in the code, with tests)

| ADR | Change | Where |
|---|---|---|
| ADR-035 | Re-order MuPDF's OCR lines into column order by geometry. Before this, two-column scans came out interleaved line by line. | `backend/parsers/reading_order.py`, `ocr.py` |
| ADR-036 | `engine="glm-ocr"` sends only a PDF's **image-only** pages to GLM-OCR. Text-layer pages go to PyMuPDF. Each consecutive run of scans is one request, and a failed run falls back to Tesseract for those pages only. | `backend/parsers/file_parser.py` (`_glm_ocr_pdf`) |
| ADR-037 | Drop OCR text read out of photographs (large mid-tone regions; banner text that reads as words survives). Render OCR rows by line centre. Both are behind flags: `ocr.SKIP_PHOTO_REGIONS`, `reading_order.ROWS_BY_CENTRE`. | `backend/parsers/photo_regions.py`, `reading_order.py`, `ocr.py` |

The tests pass: 490 passed, 8 skipped. No API contract change.

Net effect on the **default** scanned-page path, over all 26 hand-checked scanned
pages: wer **0.209 → 0.149**, same speed (~4 s/page). That is ADR-035 plus ADR-037
against the pre-ADR-035 path; ADR-035 alone took two-column scans from ~0.65 to ~0.11.

## The benchmark harness (`benchmarks/bakeoff/`)

Three samples of hand-transcribed pages, each with its own answer keys. These
references are the session's most valuable output.

| Set | Pages | How the references were made | Role |
|---|---|---|---|
| A (`SAMPLE`) | 4 born-digital (V16) + 6 scans | Scans: corrected from Tesseract drafts, **so they may favour Tesseract** | original sample |
| B (`SAMPLE_B`) | 10 scans | **blind**: transcribed from images before any engine ran (`88b99f4`) | development |
| C (`SAMPLE_C`) | 10 scans | **blind**, committed before ADR-037 was written (`1f0986a`) | held-out test; now *used* |

- `run_engines.py <engine> [--set a|b|c]`: engines are `pymupdf` (default path),
  `tesseract-adr035` (pre-ADR-037 baseline, via the flags), `tesseract-unordered`
  (pre-ADR-035), `tesseract-psm3` (the Tesseract CLI with its own layout analysis),
  `docling`, and `glm-ocr`. Timings merge into `outputs/<engine>/timings.json`.
- `score.py [--set b|c]`: wer, word recall/precision and number recall/precision,
  per page, per group and per set.
- `vote.py` (ROVER voting and consensus routers), `route.py` (the rejected set-B
  router), and `disagreements.py` (adjudication helper).
- `adjudication/log.md`: every change made to a blind reference, and why.
- Write-ups: `docs/benchmarks/2026-11-03-*.md`. Read them in this order:
  `voting-experiment`, `tesseract-reading-order`, `set-b`, `set-c`.

| oracle (best of default / psm 3 / GLM-OCR per page; cheats) | 0.037 | 0.974 | 0.932 | — |

What these numbers mean:

- **The set-B router failed its held-out test** (set C wer 0.190, against GLM-OCR's
  0.100). Do not ship it. `route.py` stays only as a record.
- **Tesseract psm 3 beats the default path on 18 of 26 pages.** It loses only on
  pages read row by row: the typewriter tables (V2 p12, p14, p17) and the
  name/number lists (V4 p25, V4 p32). It reads those one column at a time.
- **The default path's weak spot is mixed layouts.** ADR-035's geometric column
  detection fails on a table inside a column (V4 p23, wer 0.932) and on a table
  above two-column text (V4 p19, 0.563). psm 3 reads them at 0.016 and 0.194.
- **Voting loses to choosing one engine per page.**

## Open decision and the next step

The leading design candidate, not yet implemented:

> **Scanned pages: Tesseract psm 3 by default; today's MuPDF + ADR-035/037 path
> for pages that must be read across rows (tables and lists). GLM-OCR stays
> opt-in, mainly for number recall.**

Before that can be built and trusted:

1. **Find a better table/list signal than "≥ 30% numbers".** That rule misroutes
   V4 p19 (0.33 numbers, but psm 3 is better there) and V4 p25 (0.23 numbers, but
   the default path is better).
   - Candidate signal: many rows whose fragments align vertically across the page
     (shared column x-positions repeating over several rows), as opposed to prose
     columns.
   - Develop it on sets A, B and C only.
2. **Build set D**, a fresh held-out set, before shipping.
   - **The user is getting more scanned journals with tables.** The three PDFs in
     `pdf-test/` have no unused table pages left (only V2 p19).
   - When new PDFs arrive, follow the set B/C procedure exactly (below).
3. **Implementing psm 3 means leaving ADR-012's MuPDF OCR primitive for those
   pages.** That needs a new ADR.
   - Render the page at 300 dpi and run `tesseract stdin stdout --psm 3`, as
     `run_engines.py`'s `tesseract_psm3_engine` does.
   - The output is deterministic for fixed pixels.
   - It must still pass through `clean_markdown()` and keep ADR-014's fallback.
4. **Smaller follow-ups:**
   - Photos on near-black backgrounds are not caught by ADR-037.
   - The UI's progress estimate still assumes minutes for any PDF under
     `glm-ocr` (ADR-036 made born-digital PDFs fast).
   - GLM-OCR runs of more than 20 scanned pages are not chunked to the service's
     page cap.

## How to build a new held-out set (the procedure that worked)

1. **Survey.** Run Tesseract once over every image-only page: word count, number
   share, columns found. The survey script was in the session scratchpad; its
   logic is in `docs/benchmarks/2026-11-03-set-b.md` § "How the pages were
   chosen".
2. **Draw.** A seeded stratified random draw across the layout groups: two-column
   prose, tables (≥ 30% numbers), two-column + data, single column. Exclude every
   page already used **and every duplicate scan of one**.
   - V2's PDF scans four journal pages twice: p15 = p5, p16 = p6, p17 = p13,
     p18 = p14.
   - Map scans to printed page numbers to catch duplicates. Pixel diffs miss
     shifted scans.
3. **Transcribe blind** from high-resolution crops (≥ 200 dpi; 230–260 dpi for
   small table type), before any engine runs. Conventions:
   - read column by column;
   - read tables row by row, a multi-line cell line by line across;
   - skip text inside photos;
   - put the page number last;
   - keep printed typos and defects ("cserrations", "tne", "4CB");
   - use the real characters (degree sign "°", not the ordinal "º").
4. **Commit the references before running anything.**
5. **Run engines one at a time**, never side by side on this 4-vCPU box. Commit
   outputs as they land.
6. **Adjudicate.** Run `disagreements.py --set <x> --min 2`, check each listed word
   on a zoomed crop, change a reference only if the image shows it was wrong, and
   log every decision.

## Re-creating the engine environments

The scratchpad venvs do not survive the session.

- **Tesseract:** `apt-get install -y tesseract-ocr` and
  `pip install -r backend/requirements.txt -r backend/requirements-dev.txt`.
- **docling:** a separate venv with
  `pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision`,
  then `pip install "docling==2.145.*" easyocr pymupdf==1.28.0`. Run
  `run_engines.py docling` with that venv's python. Its first run downloads the
  models.
- **GLM-OCR:**
  - **Install:** a separate venv with the CPU wheels
    `torch==2.15.0 torchvision==0.29.2`, then `pip install -r
    glm-ocr/requirements.txt`.
  - **Weights:** download them at the revisions pinned in `glm-ocr/Dockerfile`,
    and write `refs/main` for each, as the Dockerfile does.
  - **Start:** `model_server.py` (port 8080), then `service.py` with `PORT=7861`.
    Use `HF_HUB_OFFLINE=1 GLM_OCR_THREADS=4 GLM_OCR_DTYPE=bfloat16`.
  - **Run:** `run_engines.py glm-ocr http://127.0.0.1:7861 --set <x>`. It takes
    roughly 30–230 s per page.

## Pitfalls hit this session (don't repeat them)

- **`pkill -f <pattern>` / `pgrep -f <pattern>` matched the shell running them**
  and killed the whole command chain (exit 144) twice. Use `pgrep -f "[m]odel_server"`
  or kill by PID.
- **`git push` from this container sometimes hangs for minutes** but does land.
  Check with `git fetch` and compare `HEAD` with `origin/<branch>` before retrying.
- **The scorer once deleted ~110 words** because its HTML-tag regex matched
  across lines between stray `<` and `>` OCR specks. That is fixed (single-line
  tags only). Re-score everything if the tokenizer changes.
- **Tuning on the test set:** both the router and the post-hoc policies above were
  chosen after seeing the pages they are scored on. Only held-out numbers count as
  evidence.
- **Paid outputs must be committed immediately.** The 2026-11-01 GPT/Gemini
  outputs were lost with their container (see the post-mortem).

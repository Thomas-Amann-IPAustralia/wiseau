## What happened

1. **ADR-042 (ships, default path).** `tesseract_layout.keeps_words` compares
   *plausible* word counts, so speckle can't make a junkier guard text win (P85 p5's
   address line is back). Across all 336 scanned pages of the 16 test PDFs the
   choice flips on 11: 8 better, 3 marginally worse on junk-only pages; no scored
   page changes. `ocr.PLAUSIBLE_GUARD = False` restores the raw count.
2. **The default's output depended on machine load (fixed in ADR-042).** The
   OpenMP `tesseract` CLI oversubscribes the CPU when several run at once; psm 3
   then passed its 120 s timeout and the guard text came back. Seen on 5 set F
   pages and in the live test while other jobs ran. `read_page` now sets
   `OMP_THREAD_LIMIT=1`: byte-identical text, 2–5 s per pass. All 76 scored pages
   reproduce byte for byte with three other jobs running.
3. **1.2 preprocessing ablation: nothing ships.** Deskew, deskew + normalisation,
   Sauvola, denoise, against a pixel-exact round-trip control (`pre-ident`, which
   reproduces the default on every page). All lose. Rotation by 0.1–0.3° breaks
   psm 3's table blocks; binarising hides photos from ADR-037's mask.
4. **1.3 bake-off: nothing ships.**
   - PaddleOCR recognisers lose as line readers (they drop spaces in table rows).
     Re-reading Tesseract's *word* boxes, PP-OCRv6 small gains 0.004 wer, at 4× the
     time and 2.7 GB. No help on the 1963 typewriter faces.
   - **Table Transformer fixes V5N1 p18** (side-by-side tables, 0.327 → 0.062) and
     rescues V1N3 p16. But at threshold 0.8 it boxes two-column prose pages as one
     table and interleaves the columns (+0.101 overall, held out +0.134). Neither
     its confidence nor ADR-038's stitch signal separates the cases.
   - PP-StructureV3 is worse than the default on its own table pages (wer 0.332 vs
     0.090), loses text, merges side-by-side tables, and needs 6.3–10.6 GB a page.

## Findings to carry forward

- **Table Transformer is the best lead for side-by-side tables, and needs a
  prose-vs-table check** on each detected region before it is read row by row
  (short cells, numbers, aligned columns vs long lines and sentence punctuation).
  That is roadmap 3.7 (region routing). Design it on the development sets (A–D, L),
  hold it out on E and F. TATR's raw detections for every scored scan are in
  `survey/tatr-detections.json` (`tatr_detections.py`).
- **Layout is fragile.** A 0.1° rotation changes psm 3's table blocks; anything that
  touches pixels must be judged on reading order (`ord`) as well as wer.
- **Run heavy jobs side by side only with one thread each** (`OMP_THREAD_LIMIT=1`,
  `PADDLE_THREADS`, `TATR_THREADS`). Oversubscription is what made Tesseract slow.
- The bake-off's `rec-tesseract` control skips ADR-038's guard and ADR-041's band
  cleanup; it scores 0.067 on the 72 scans against the default's 0.056.

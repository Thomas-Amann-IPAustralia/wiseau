# Tables on scans: Table Transformer in the default path, and the table dialect (2026-11-09)

Roadmap Phase 14, items 3.7 (region routing for tables) and 2.2's second half
(the explicit Markdown dialect). ADR-045, ADR-046. No paid API was used; every
model is local and free.

## What was built

- **`parsers/tables.py` (opt-in, `WISEAU_TABLES=tatr`).** On each OCR'd page,
  Table Transformer's detection model proposes table regions and its structure
  model their rows and columns. The words Tesseract already read fill the cells,
  each word into the row and column it overlaps most (rows are assigned per
  Tesseract line, so a slightly skewed scan cannot shift a value into the next
  row). A TATR row that stacks several records ("mean / range / std deviation")
  is split into one row per printed line. A region whose cells average more than
  **2.5 words** is refused as prose boxed as a table. An accepted region's words
  leave the page's text elements and become one IR `table` element with real
  cells. No word is re-read, added or lost.
- **The dialect (`serializer.py`).** A table with real cells is written as a
  Markdown pipe table when its first row is a header, else as an HTML `<table>`.
  ADR-038's stitched tables (rows of Tesseract line fragments, not columns) stay
  plain text: written as tables they gain nothing (set S TEDS 0.279 → 0.288) and
  would pretend to columns they don't have.

With the pass off (the default), the output is **byte-identical** to before:
all 15 test PDFs converted whole, and every scored page.

## How the settings were chosen

On the development sets (A–D, L) only, from a cached run of every scored scan
(`tatr_eval.py`): row splitting none/aligned/every-line, TATR's spanning cells
on/off, and the words-per-cell limit from 2.5 to no check at all. The chosen
setting (aligned split, no spanning cells, ≤ 2.5) was best or tied on the
development sets on both words and structure, then run unchanged on the
held-out sets (E, F) and end to end (`run_engines.py tables-tatr`, which matches
the cached evaluation on all 72 scans).

**Protocol note.** The coarse-row problem the row split fixes was first seen on
V2N2 p10, a held-out (set F) page; it shows equally on development pages (V2
p12, p14, p17), and no setting was chosen on held-out numbers. Set S (structure)
is mostly development pages: S04 (V4N1 p7, set F) and S05 (P63a p7, set E) are
its only held-out documents.

### The tabularity check

Every region TATR proposed at ≥ 0.8, read as a table on its own:

| | Regions | Mean effect on the page's wer | Regions costing > 0.1 wer |
|---|---|---|---|
| Development, accepted | 28 | −0.007 | 0 |
| Development, refused | 12 | +0.458 | 9 |
| **Held out, accepted** | 8 | +0.012 | **0** |
| **Held out, refused** | 8 | +0.501 | 7 |

The refusals are two-column prose and patent pages boxed whole as tables (V2
p4, V2N2 p4, WO06 p4, P00 p15) and mixed regions. At a limit of 3.0 instead of
2.5, held-out V4N1 p27 (2.98 words a cell, +0.71 wer) would have been accepted:
the development sets chose the safer value.

| Seconds per scanned page (17 set S scans) | 7.1 | **9.0 (+26%)** | 7.8 (+8%) |
| TATR's own time per page | | 1.6 (0.6 with no table, up to 3.6 with two) | 0.6 |

| Peak memory of the process | 282 MB | 1,174 MB | 1,171 MB |
| Docker image (uncompressed) | 2.0 GB | 3.9 GB (+1.9 GB: PyTorch and its dependencies, 230 MB of models; ADR-047) | |

A whole table-heavy document, Vol 5 No 1 (31 scanned pages, one thread, model load
included): **227 s → 273 s (+20%)**, with 23 tables written as tables. With the
pass off it is byte-identical to the default.

Born-digital pages never run it (they have no OCR step). One thread per job is
what the service would use: it runs up to four conversions at once, and the
OCR path already holds Tesseract to one thread for the same reason (ADR-042).
Output is identical at 1, 2 and 4 threads and across repeated runs.

## Recommendation

**Turn it on in the deployed Space; keep it optional in the code.** The gain is
large and is the one the user's frontier review asked for (tables that are
tables): table structure more than doubles (TEDS 0.26 → 0.56), it beats docling
on tables and matches GLM-OCR on the comparison tables, while losing no text and
refusing every damaging region on the held-out sets. The cost is +2 s per scanned
page (+26%; +20% on a whole table-heavy volume), nothing on born-digital pages,
about 1 GB more memory (the Space has 16 GB), and +1.9 GB of image.

**Done (ADR-047), after the user accepted:** `backend/Dockerfile` installs CPU
PyTorch and `requirements-tables.txt`, fetches the two pinned models at build
time (so no conversion depends on Hugging Face being reachable), and sets
`WISEAU_TABLES=tatr`. Setting the variable to empty switches it off again
without a rebuild; `--build-arg TABLES=0` builds without PyTorch.

Keep it off if image size or cold-start time matters more than tables (a
deployment for born-digital PDFs gains nothing from it). A per-request switch is
possible later but would be an API contract change.

## In the built image (ADR-047, after the user accepted the recommendation)

Built from `backend/Dockerfile` and run with **no network** (models fetched at
build time, `HF_HUB_OFFLINE=1`), as the Space's UID 1000:

| | Result |
|---|---|
| V5N1 p18 over HTTP, first request (model load included) | 14.7 s, both tables returned as tables |
| Same, warm | 10.8 s |
| Four scanned table pages at once | all four succeed, 26.9 s wall; peak process memory 1.9 GB |
| Lean image (`--build-arg TABLES=0`) | 2.0 GB; converts, no tables |

Load-testing found a pre-existing bug unrelated to tables: MuPDF's OCR call is not
thread-safe, so concurrent scanned uploads failed with a 502 on any image. It is
fixed by serialising that one call (ADR-047).

## What it does not do

- Born-digital tables (PyMuPDF4LLM's Markdown, e.g. V16 p90) are untouched.
- Tables TATR misses at 0.8 (S08's provisional list, S09's fee table) and tables
  with longer cells (lists of names and application numbers) stay as text.
- Spanning cells are not used: on the development sets TATR's spanning-cell
  boxes cost words and structure both.
- No headings, no emphasis: those are roadmap 3.1 and font detection.

## Reproduce

```bash
pip install --index-url https://download.pytorch.org/whl/cpu torch==2.15.0 torchvision==0.29.2
pip install -r backend/requirements-tables.txt
python benchmarks/bakeoff/tatr_eval.py cache /tmp/tc a b    # (and c d, l e, f)
python benchmarks/bakeoff/tatr_eval.py eval /tmp/tc         # the settings grid
python benchmarks/bakeoff/run_engines.py tables-tatr --set d  # end to end, each set
python benchmarks/bakeoff/structure.py --docs
python benchmarks/bakeoff/table_timing.py /tmp/t1.json --threads 1
```

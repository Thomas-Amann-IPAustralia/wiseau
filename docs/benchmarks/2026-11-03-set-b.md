# Set B: ten new, independently transcribed scanned pages: 2026-11-03

**Why:** every earlier comparison of the self-hosted engines rested on six scanned
pages whose answer keys were drafted from Tesseract output and then corrected.
That could flatter Tesseract, and six pages is too few to base a design on. Set B
adds ten pages whose answer keys were written from the page images alone, before
any engine was run on them.

No paid API was used. Everything here ran on the session's container: 4 vCPU,
15 GB RAM, no GPU. Engines ran one at a time.

## How the pages were chosen

1. **Survey:** all 62 image-only pages in the three PDFs (V2: 28, V4: 32, V16: 2)
   were run through Tesseract once. That gave each page's word count, number share
   and whether the column detector (ADR-035) finds columns.
2. **Layout groups:** pages were assigned to five groups. "Two-column prose" (22
   pages) has two columns and under 12% numbers. "Tables" (8 pages) is at least 30%
   numbers. "Two-column + data" (13 pages) has two columns and 12–30% numbers.
   "Single column" has 11 pages. Near-empty pages (8, such as covers, blanks and
   photo pages) were left out.
3. **Seeded random draw:** 3 + 2 + 3 + 2 pages, seed 20261103, excluding set A's
   six scanned pages.
4. **Duplicates found and replaced.** V2's PDF scans four journal pages twice:
   p15 = p5, p16 = p6, p17 = p13 and p18 = p14. These were found by mapping each
   scan to its printed page number.
   - The draw first picked V2 p13 (journal page 11, the same page as set A's V2
     p17) and V2 p16 (journal page 4, the same page as set A's V2 p6).
   - They were redrawn from their groups with seeds 20261104 and 20261105, which
     gave V2 p14 and V2 p23.
   - This also means set A's V2 p17 is one of a duplicate pair.

| Group | Pages |
|---|---|
| Two-column prose | V2 p9, V2 p11, V2 p23 |
| Tables | V2 p14 (typewriter comparison table), V4 p32 (two-column list of titles and dates) |
| Two-column + data | V4 p8 (pumpkin table + prose), V4 p22 (rose table + prose), V4 p25 (application lists) |
| Single column | V2 p2 (contents), V4 p27 (dense directory, many phone numbers) |

## How the answer keys were made

1. **Blind transcription.** Each page was transcribed by reading high-resolution
   crops of the page image, before any engine was run on set B. These were
   committed as they stood (`88b99f4`), so any later change shows up as a diff.
2. **Conventions, as in set A:**
   - reading order is column by column;
   - tables are read row by row, with a cell's lines read across;
   - text inside photographs is skipped;
   - the page number comes last;
   - printed typos are kept as printed ("cserrations", "tne").
3. **Adjudication.** `benchmarks/bakeoff/disagreements.py` aligns each engine's
   output to the reference and lists the words where engines read something else.
   - Agreement counts per recogniser family: the two Tesseract runs count once,
     and docling's EasyOCR and GLM-OCR are the other two.
   - Each listed word was checked against a zoomed crop. The reference was changed
     only when the image showed it was wrong.
   - Every change is in `benchmarks/bakeoff/adjudication/log.md`.

## Engines

| Name | What runs |
|---|---|
| `pymupdf` | The default path: PyMuPDF → MuPDF's Tesseract at 300 dpi → ADR-035 reading order |
| `tesseract-unordered` | The same, with ADR-035 switched off (the order before today) |
| `tesseract-psm3` | The Tesseract CLI with its own page-layout analysis (psm 3), 300 dpi |
| `docling` | The docling library with EasyOCR, table structure on |
| `glm-ocr` | `glm-ocr/service.py` (PP-DocLayoutV3 + GLM-OCR, bf16, 4 threads, repetition penalty 1.0) |
| `vote-*`, `consensus-*`, `oracle-best-single` | `vote.py` over pymupdf / docling / glm-ocr, as before |

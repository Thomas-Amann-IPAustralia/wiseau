# Set D: held-out test of Tesseract's own layout with table-row stitching: 2026-11-06

**Why:** set C left one design candidate open: read scans with Tesseract's own
layout analysis (psm 3), but keep today's path for pages that must be read across
rows. It needed a better table signal than "≥ 30% numbers", and a fresh held-out
set, because every unused table page in the first three journals was gone. The
user supplied four more PDFs. Two of them (Vol 5 No 1 and Vol 5 No 3) are
image-only scans, and set D comes from them.

No paid API was used. Engines ran one at a time on the session container (4 vCPU,
15 GB RAM, no GPU).

## Order of work (what makes this a held-out test)

1. **Survey and draw.** `benchmarks/bakeoff/survey.py` ran Tesseract once over the
   58 image-only pages: word count, number share, columns found by ADR-035, and
   first/last lines. Groups as for sets B and C; 15 near-empty pages (covers,
   photo pages) were left out. Seeded draw (seed 20261107), 3 + 3 + 4 + 2 pages:
   - two-column prose: V5N3 p12, p17, p23;
   - tables: V5N1 p11, V5N1 p20, V5N3 p19;
   - two-column + data: V5N1 p9, p18, p19, V5N3 p24;
   - single column: V5N1 p24 (really a table, then two columns with a table in
     the right one), V5N3 p4 (editorial with a column of portraits).

   Every drawn page maps to a distinct printed page number, so there are no
   duplicate scans (V2's PDF had four).
2. **Blind transcription** from 200–450 dpi crops, before any engine ran on these
   pages, under the set B/C conventions. These two issues are printed with a worn
   "e" that reads as "c", and those are kept as printed ("thc", "Kicntzler",
   "Rcsearch"). Committed as `451a718`.
3. **Design on sets A–C only.** The stitching rule and the guard (below) were built
   and swept on the 26 earlier scans, then **frozen** behind
   `ocr.TESSERACT_LAYOUT = False` in `9790218`.
4. **Run on set D**, Tesseract family first (committed unseen), then docling and
   GLM-OCR.
5. **Switch the flag on** (`f702b8b`), then adjudicate (below; no reference
   changed, so no score moved).

## The design

Tesseract psm 3 already reads mixed pages well. Its one failure is cutting each
table column into its own block. Instead of a page-level router, the fix works
inside psm 3's output:

- **Stitch** side-by-side blocks that look like table cells into one table, read
  row by row. Cells have median ≤ 4 words per line and are ≤ 40% of the text
  width. They must overlap vertically, be ≤ 20% of the text width apart, and
  ≥ 60% of the smaller block's lines must match a line of similar height at the
  same height. Prose columns have long lines, so they never stitch.
- **Guard:** keep the ADR-035/037 text. If psm 3's text has < 85% of its words,
  use the guard. On the dev pages this fired only on V4 p32 (psm 3 had dropped
  the whole date column, 54% of the words). Every other page was ≥ 96%.

On sets A–C (tuned there, so optimistic): wer 0.149 → 0.048. A parameter sweep
moved the mean by at most 0.02, and only at the extremes (gap 0.10, width 0.50).

## Adjudication

All four recogniser families were present (Tesseract through two paths, docling's
EasyOCR, GLM-OCR). `disagreements.py --set d --min 2` listed 75 words. Examples of
each kind were checked on 600–700 dpi crops, and **no reference was changed**:

- **Worn "e" printed as "c"** (about 30 words: "thc", "pletc block dcsign"). At
  600 dpi the letters have no crossbar. The engines "correct" them.
- **Units printed with a space** (about 30: "18.3 cm" read as "18.3cm").
- **Printed line-end hyphens** ("mid-/line"), kept as in sets A–C.
- A sans-serif capital I read as "l" ("PI 13768"); "See" read as "sce"; "3–4" as "34".

The worn letters cost every engine the same words, so they do not change the
ranking. Details: `benchmarks/bakeoff/adjudication/log.md`.

## Findings

1. **The design holds on unseen pages.** Held out, the new default is 0.279 → 0.072
   against the old one, better on 10 of 12 pages, with higher word and number
   recall. It also beats GLM-OCR (0.095) at about 1/14 of the time, and finds more
   numbers (0.973 against 0.917).
2. **Most of the gain is psm 3; stitching adds the rest where cells occur.** psm 3
   alone scores 0.094. Stitching changed 2 of 12 set-D pages: V5N3 p24 0.404 →
   0.133, V5N3 p17 0.033 → 0.036. On the dev sets it fixed the list and
   typewriter-table pages psm 3 lost (V4 p25 0.388 → 0.003, V2 p17 0.093 → 0.024).
   This issue's tables are mostly ruled, and psm 3 keeps ruled rows whole.
3. **The guard did not fire on set D.** psm 3 kept ≥ 85% of the words on every
   page.
4. **Two losses, both reading-order:**
   - **V5N1 p18** (0.130 → 0.299): two tables side by side are read across both.
     psm 3 alone does the same. GLM-OCR reads this page best (0.092).
   - **V5N3 p24** (0.044 → 0.133): the left column's committee entries are short
     address lines, so they look like cells and were stitched to the right
     column's directory across the column gutter. The old default read this page
     well because it is two clean columns.
5. **Mixed pages are fixed.** Pages with a table inside a column were the old
   default's worst case. They now score 0.004–0.060 (V5N1 p24 0.605 → 0.060,
   V5N3 p12 0.257 → 0.004).
6. **docling is again the weakest scan engine** (0.343; 0.924 on V5N1 p9).

## Open items

- **Don't stitch across a text-column gutter.** V5N3 p24's committee entries in
  the left column are short address lines. They look like cells and were stitched
  to the right column's directory. A fix needs a new held-out set (E).
- **Side-by-side tables** (V5N1 p18) are read across both tables. psm 3 alone does
  this, so it predates stitching.
- **Hidden OCR layers** (Vol 1 No 3). The default path trusts Acrobat's layer
  (ADR-036 already lists this blind spot). A quick check without references:
  the layer agrees with a fresh OCR on 99% of words on prose (p4), but on 82% on
  its table page (p11), where the layer reads table columns top to bottom.
  Whether re-OCR would be better needs references.
- **Misread text passes the guard.** It counts words, so it catches dropped text,
  not wrong text. On a synthetic page with identical text on every line, psm 3
  removed the stacked letters as table rules.

## Caveats

- 38 scans from four issues of one publication.
- The scorer measures words, numbers and reading order, not Markdown structure.
- Timings are this container's; the new default runs two OCR passes per scan.

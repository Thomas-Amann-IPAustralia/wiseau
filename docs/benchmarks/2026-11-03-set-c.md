# Set C: held-out test of the ADR-037 fixes and the per-page router: 2026-11-03

**Why:** two things were designed on sets A and B, and needed pages they had never
seen:
- the two Tesseract fixes (photo noise, row chaining; ADR-037);
- the per-page router from [set B](2026-11-03-set-b.md).

Set C is ten scanned pages, blind-transcribed before either fix was written and
before any engine ran on them.

No paid API was used. Engines ran one at a time on the session container (4 vCPU,
no GPU).

## Method

- **Pages.** A seeded stratified draw (seed 20261106) over the 62 image-only pages,
  excluding sets A and B and every duplicate scan of their pages. Same layout groups
  as set B:
  - two-column prose: V2 p4, V2 p8 (photos), V4 p17;
  - tables: V2 p12 (typewriter), V4 p19 (wax-flower table + two-column prose);
  - two-column + data: V2 p21, V4 p10, V4 p14;
  - single column: V4 p3 (portrait photo + full-width text), V4 p23.
    The detector calls V4 p23 single-column, but it is really two columns with a
    table in the left one.
- **Order of work:**
  1. The blind references were committed (`1f0986a`).
  2. The pre-fix default path was run on set C and committed unseen as
     `tesseract-adr035` (`285cd82`).
  3. The fixes were designed on sets A and B only (`4950632`).
  4. Every engine was then run on set C.
- **Adjudication:** as for set B. Two references were changed, both logged in
  `benchmarks/bakeoff/adjudication/log.md`. V4 p14 "40B" became "4CB", as printed
  (a broken zero). On V4 p10 I had typed a masculine ordinal "º" where the page
  prints a degree sign "°".

## Findings

1. **The ADR-037 fixes generalise.**
   - Held out: wer 0.326 → 0.256, and no set C page is worse.
   - The photo fix does what it was built for on unseen pages: V2 p8 0.598 → 0.066,
     V4 p14 0.358 → 0.274, and two-column prose overall 0.278 → 0.088.
   - Over all 26 pages the default path goes from 0.209 to 0.149 at the same speed.
2. **The set-B router does not generalise, so it should not ship.** On set C it
   scores 0.190, worse than GLM-OCR alone (0.100) and psm 3 (0.076).
   - Its "single column → Tesseract" branch fired on V4 p23 and V4 p3. On V4 p23
     the column detector *failed*: it is two columns with a table inside one, and
     the default path read it at 0.932.
   - Its "≥ 30% numbers → Tesseract" branch sent V4 p19 (a table above two-column
     prose) to the default path, where it scored 0.563.
   - Both signals were weaker than set B suggested.
3. **The biggest remaining weakness is ADR-035's geometric layout on mixed pages,
   and Tesseract's own layout analysis already solves most of it.**
   - psm 3 beats the fixed default on 18 of 26 pages and loses on 5.
   - All 5 losses are pages that must be read across each row: three typewriter
     tables (V2 p12, p14, p17) and two name/number lists (V4 p25, V4 p32). psm 3
     reads those one column at a time.
   - On everything else (mixed table-and-prose layouts, photos, banners) psm 3 is
     as good as GLM-OCR or better, at about 3 s/page against 98.
4. **GLM-OCR and psm 3 are level on word order over 26 pages** (0.092 against
   0.093). GLM-OCR finds more numbers (0.895 against 0.852) at about 30 times the
   time.
5. **docling is again the weakest scan engine.** It failed outright on the V2 p12
   typewriter table (61 characters of output).

## What this means for the design

- **Ship ADR-037.** Merged into the default path, it is validated on held-out
  pages.
- **Do not ship the set-B router.** It failed its held-out test.
- **The evidence points to a different default for scans:** Tesseract's own
  layout analysis (psm 3) for most pages, keeping today's MuPDF + ADR-035/037 path
  for pages that must be read across rows (tables and lists).
  - The obvious split ("≥ 30% numbers → today's path, else psm 3") scores 0.077 at
    6 s/page over all 26 pages. That is better than GLM-OCR alone at 1/15 of the
    time.
  - But that rule was chosen after seeing set C, and it still misroutes V4 p19 and
    V4 p25. A better table/list signal (rows aligned across the page, rather than
    number share) is the open design question.
  - Either way it needs a fresh held-out set D.
- **The table supply is the bottleneck for set D.** Every unused table page in
  these three PDFs is now gone except V2 p19 (V2 p18 is a duplicate). More scanned
  journals with tables are needed for a fair test.
- **GLM-OCR stays opt-in.** Its remaining advantage is numbers (0.895 against
  0.852), on the pages where that matters.

## Caveats

- 26 scanned pages from two journals of one publication.
- The post-hoc policies above are *not* held-out results.
- The scorer measures words, numbers and reading order, not Markdown structure.
- A psm 3 path would also need its own photo handling check. It skipped photos
  well here, but that was not separately tested.
